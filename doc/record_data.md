# 记录数据格式（record data）

本文说明电压电流记录落到磁盘上之后**是什么**：一份 CSV 的列语义、会话如何切分、`index.json` 各字段意味着什么，以及中断在数据里长成什么样。复看页的操作方式见 `doc/record_review.md`。

范围仅限数据：应用不提供删除、轮转或截断记录的能力，磁盘回收由用户自行处理。

## 位置与开关

| 项 | 值 |
|---|---|
| 配置文件 | `config/record_settings.json`（打包运行时在 exe 同级），带 `version` 字段，tmp + `os.replace` 原子写 |
| 默认 | `enabled=false`、`dir="records"`；配置缺失或内容不可用一律回落这套默认值，不抛异常 |
| 采样周期 | 不是配置项：面板轮询节奏来自代码常量 `recording/settings.py` 的 `NOMINAL_INTERVAL_MS`（当前 500 ms），改配置文件不会改变采样 |
| 记录目录 | 相对路径按仓库根（或 exe 同级）解析；会话 CSV 与 `index.json` 都在这里 |
| 文件名 | `<YYYYMMDDTHHMMSS>_<端口>.csv`，同一秒内重连则追加 `_2`、`_3`…，绝不覆盖已有文件 |

记录默认关闭，且只在"使能 + 设备已连接"同时成立时才建文件；先开开关后连接，文件在连接成功那一刻才出现。

## CSV 列语义

一个采样周期一条记录，四列固定：

```
ts_ms,iso_local,voltage_v,current_a
1795269513790,2026-11-21T21:58:33.790+08:00,12.01,1.01
```

| 列 | 含义 |
|---|---|
| `ts_ms` | epoch 毫秒，整数。取时间点的时机在**电压与电流都读到手之后**：先取会把串口往返耗时算进采样间隔 |
| `iso_local` | 同一时刻的本地 ISO 字符串（带时区偏移、毫秒），给人和表格工具看；判读时序以 `ts_ms` 为准 |
| `voltage_v` | `MEASure:VOLTage?` 的返回值，单位 V |
| `current_a` | `MEASure:CURRent?` 的返回值，单位 A |

数值列按 `csv` 模块的默认方式写 floats 的原样文本，不做补零或定宽处理，所以同列的字符宽度可能不一致。

行分隔用 `\r\n`（`csv` 模块默认），列头在首行。写入带缓冲，每 2 秒 flush 一次，退出（关窗/断开/关闭使能）时 flush + close。

体积估算：24 小时约 17.3 万行、9 MB。

## 会话切分与清单

一次会话 = 一段"记录使能且设备已连接"的时间。断开连接、关闭使能、关窗三种路径各自结束当前会话；重连则另起一份新 CSV。

`index.json` 是这段数据存在过的唯一凭据：

```
{"version": 1, "sessions": [{"id": "...", "file": "...", "port": "COM8",
  "started_at": "...", "ended_at": "...", "rows": 500, "bytes": 26000, "status": "closed"}]}
```

| 字段 | 含义 |
|---|---|
| `id` | 会话标识，即 CSV 文件名去掉扩展名 |
| `file` | 数据文件名，相对记录目录 |
| `port` | 建立会话时连接的串口 |
| `started_at` / `ended_at` | 本地 ISO 时刻；`ended_at` 在会话进行中为 `null` |
| `rows` / `bytes` | 记录条数与文件字节数 |
| `status` | `recording`（进行中）、`closed`（正常结束）、`interrupted`（异常退出后改判） |

条目按 `started_at` 升序落盘；清单读写都是整份原子替换。**一行都没采到的会话不登记，也不留空文件。**

## 缺口在数据中的表现

采样失败的周期**不产生任何行**——没有插值、没有外推、没有占位行。所以中断只以"相邻两条 `ts_ms` 之差变大"的形式存在：

```
1767196800123   ← 最后一次成功
1767196809500   ← 与上一条相差 9.4 秒：这中间掉线了
```

复看侧以 `相邻 ts_ms 差 > 2.5 × 标称采样周期` 判定缺口并断段（倍数见 `src/recording/reader.py` 的 `GAP_FACTOR`，周期见 `src/recording/settings.py` 的 `NOMINAL_INTERVAL_MS`）。也就是说：单次失败（约 2 个周期）仍在同一连续段内，连续两次以上失败才会断开。

## 异常退出与 `interrupted`

进程被杀、断电、崩溃时，清单里会留下一条 `status=recording` 的条目。下次启动时应用按数据文件的**实际行数与大小**回填 `rows`/`bytes`，把 `ended_at` 置为文件里最后一条记录的时刻，并改判为 `interrupted`；数据文件保持可用。

因此 `interrupted` 的含义是"这段数据没有正常收尾"，不是"数据不可用"。已经 flush 出来的行都在文件里；最后不到 2 秒（一个 flush 周期）的样本可能随缓冲区丢失。

手工编辑过或被截断的文件不会让读取失败：无法解析的行被跳过并计数，复看页在读数里报出跳过条数，能画出来的部分照样画出来。
