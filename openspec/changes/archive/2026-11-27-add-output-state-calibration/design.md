# Design

## Context

见 `proposal.md` 的动机与 `specs/ui/output-control/spec.md` 的行为契约。当前输出状态分散在三处：悬浮窗固定发送 `False`，主窗口按钮使用自动勾选值，Presenter 在写入后只更新按钮文字；设备实际输出可能已被远程客户端改变。校准因此必须回到设备 `OUTP?`，而不是复用 UI 或请求中的目标值。

现有 V/I 采样每 500ms 读取一次电压和一次电流，所有 SCPI 命令共用设备实例的 `asyncio.Lock`，单次命令超时为 1 秒。输出校准不能增加每轮 V/I 读取，也不能让一次状态查询长时间阻塞串口。

## Goals / Non-Goals

**Goals:**

- 建立一个以设备回读为唯一事实来源的三态输出状态。
- 主窗口按钮和悬浮窗菜单根据同一状态显示下一步动作。
- 用独立 1 秒校准任务覆盖远程和设备侧状态变化。
- 本机写入后立即回读，并防止旧校准结果覆盖新状态。
- 校准失败与 V/I 采样失败隔离，保持现有采样和记录语义。

**Non-Goals:**

- 不实现远程输出写事件通知；周期校准已经满足 1 秒同步目标。
- 不改变控制权获取、续租、接管确认或吊销规则。
- 不修改电压/电流采样周期、记录文件格式或 SCPI 远程协议。
- 不修复悬浮窗隐藏后的恢复入口，不把输出状态叠加成新的记录字段。

## Decisions

### D1. Presenter 持有三态输出状态

使用 `bool | None` 表示 `ON / OFF / UNKNOWN`，状态由 Presenter 统一维护并向视图发布。`None` 同时覆盖首次连接、断开、回读失败和不可解析响应；视图不自行猜测。

主窗口增加统一的输出状态渲染入口，同时更新按钮文字、勾选态、图标和禁用状态，并转发给悬浮窗。悬浮窗只保存最近一次发布的状态，用于构造菜单，不直接访问 Presenter 或设备。

备选方案是由主窗口或悬浮窗各自保存状态。这会重新产生双方漂移，且远程校准没有明确的唯一所有者，因此不采用。

### D2. 输出校准使用独立异步任务

连接成功后立即执行一次校准，随后每次查询完成后等待 1 秒再执行下一次。任务在断开时取消，并确保同一时刻最多只有一个校准查询。

校准循环只调用模型层的输出查询，不进入 V/I 采样循环，也不参与记录。这样 V/I 每轮仍恰好读取一次电压和一次电流，输出状态失败也不会被计入采样失败阈值。断开时同时取消采样、校准和所有在途本机切换，并等待它们退出后才关闭设备，避免旧请求在重连后继续执行。

备选方案是把 `OUTP?` 并入每 500ms 的 V/I 采集。它会把串口命令量增加约 50%，并将输出查询失败与成对采样耦合，因此不采用。

### D3. 状态查询使用短超时与严格解析

扩展设备层命令发送能力，使调用方可以为输出状态查询指定短超时；GUI 校准初始使用 250ms，其他既有命令和远程 `on_off_query` 继续保持原默认超时。

`OUTP?` 只接受去除首尾空白后的 `ON` 或 `OFF`，大小写不敏感；其他响应抛出可识别错误并进入 `UNKNOWN`。当前“非 ON 即 OFF”的解析会把乱码误报为关闭，不能满足实际状态契约。

查询读取超时或取消时，设备层记录一次待恢复响应；命令写出后的 `drain` 超时或取消也按同一规则处理，因为传输层可能已经收到命令。下一条命令发送前必须先消费这条迟到响应，恢复读取也超时则继续等待而不下发新命令。串口响应没有请求标识，若超时后直接发送下一条命令，迟到响应会被后续查询误读并持续错位。

250ms 是面向 115200 串口的初始工程值，需用模拟器和实机验证。若正常回读经常超过该值，只调整校准超时常量，不改变任务结构。

### D4. 本机切换与校准串行，写后立即回读

本机开关只发送“切换”请求，不把按钮自动勾选值当作设备事实。Presenter 先检查连接和状态是否已确认，再保留现有控制权接管确认；确认后重新读取最新已确认状态并计算目标值，随后执行写入和立即回读。接管确认在设备操作锁之外等待，避免用户长时间不操作弹窗时阻塞 V/I 采样。

校准与本机切换通过 Presenter 级的设备操作锁串行；一次 V/I 成对采集也持有同一把锁，避免旧校准结果在本机写后回读完成前覆盖新状态，同时防止超时命令的迟到响应在电压、电流和 `OUTP?` 查询之间造成响应错位。设备层原有 SCPI 锁继续保证不同来源的单条命令不会交错。断开时取消所有在途切换，确认返回或设备锁释放后都会再次检查连接状态，旧请求不得写入新会话。

按钮可以保留现有可勾选外观和主题样式，但点击只代表请求：点击后先按当前已确认状态恢复勾选，最终勾选态只能由成功回读发布。取消接管、写入失败或回读失败都不保留乐观状态。

### D5. 未知状态禁用输出操作

未连接或 `UNKNOWN` 时，主窗口按钮禁用并显示“输出状态不可用”；悬浮窗菜单项同样禁用并显示该文案。已确认 `ON` 时显示“关闭输出”，已确认 `OFF` 时显示“开启输出”。

悬浮窗输出信号改为无参数的切换请求，由主窗口转交 Presenter。菜单不再携带可能过期的目标布尔值。

### D6. 校准失败不污染采样错误通道

输出校准失败只记录诊断日志并发布 `UNKNOWN`，不调用 V/I 的采集中断提示，不把电压/电流标记为 stale。下一次成功校准自动恢复已确认状态。

这让“读数采集中断”和“输出状态暂时不可信”保持可区分，也避免一次 `OUTP?` 超时触发现有的连续采样失败阈值。

## State Flow

```text
connect success
      |
      v
OUTP? immediate -----> Presenter output state -----> MainWindow + FloatingWindow
      |                                              button / menu
      v                                                     |
every 1 second -----> same path                               |
                                                              v
                                                     local toggle request
                                                              |
                                               lease check -> OUTP ON/OFF
                                                              |
                                                    OUTP? immediate readback
                                                              |
                                                              v
                                                   publish confirmed state
```

任何 `OUTP?` 失败都把已确认状态降为 `UNKNOWN`；电压/电流采样继续走原有独立循环。

## Risks / Trade-offs

- [额外串口查询造成采样抖动] → 使用独立任务、250ms 短超时和单一在途查询；一次 V/I 成对采集与输出查询共用设备操作锁，避免超时后的迟到响应错位；验收时重跑长时采样，确认没有新增缺口。
- [远程变化最多延迟约一个校准周期] → 该延迟是已接受的产品取舍；若未来要求亚秒级同步，再评估远程写事件通知。
- [远程写入发生在本机切换确认期间] → 确认后重新读取最新状态再计算目标；设备锁保证命令顺序，周期校准兜底外部变化。
- [设备返回非标准状态文本] → 严格解析并进入 `UNKNOWN`，绝不把乱码当作 `OFF`；根据实机响应再决定是否扩展合法格式。
- [一次校准失败暂时禁用常用开关] → 1 秒后自动重试，成功即恢复；这比根据旧状态执行反向切换更安全。
- [现有测试替身缺少输出查询和状态渲染] → 同步扩展 Presenter、视图和菜单测试替身，并把“每轮只读一次 V/I”的断言保留为独立不变量。

## Migration Plan

无需数据迁移、配置迁移或远程协议变更。发布后首次连接会立即查询实际输出状态；断开和重连都重新进入 `UNKNOWN` 后再校准。

回滚时恢复原有输出菜单和按钮接线即可，已产生的 V/I 记录与窗口几何配置不受影响。
