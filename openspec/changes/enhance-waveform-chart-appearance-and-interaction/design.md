# Design

## Context

参见 `proposal.md` 的 Why 与 `specs/ui/live-curve/spec.md` 的行为契约。当前 `MainWindow._setup_chart()` 重复创建两张 `QChartView`，图表和视图背景都未显式绑定主题；`_update_chart_data()` 每次采样都会重设横轴。已有 `hovered` 处理通过 `series.atX()` 查找点，并把白底英文 `QLabel` 放在图表下方，不提供邻近点判定，也无法处理缩放后的坐标映射。

实时曲线仍以采样序号为横轴、每个窗口最多 100 个点，采样和记录链路不能因视图交互而变化。记录页的 `HistoryChartView` 使用时间轴和框选交互，不能直接复用于实时序号轴。

## Goals / Non-Goals

**Goals:**

- 用一个实时图表视图封装两张图共用的深色外观、修饰键分轴缩放、双击复位和邻近点提示。
- 将“是否自动跟随”作为视图状态，使缩放视口不会被下一次采样覆盖。
- 使用 Qt 自带的坐标映射处理高 DPI、边距和滚动偏移，避免手写绘图区插值。
- 保持现有数据窗口、采样序号、读数精度和“显示波形”门控不变。

**Non-Goals:**

- 不改变 Presenter、设备读取频率、记录格式或异常处理。
- 不加入框选、拖拽平移、跨图联动、缩放状态持久化或时间戳横轴。
- 不修改记录页、`.ui`、主题 token 值或既有曲线语义色。

## Decisions

### D1. 新增 `LiveChartView`，不复用历史图表视图

在 `src/views/live_chart_view.py` 新增 `QChartView` 子类，负责一张实时图表的 chart、series、坐标轴、背景、缩放、复位和提示。`MainWindow._setup_chart()` 只创建电压/电流两个实例并加入布局，同时保留现有 `voltage_chart`、`voltage_series`、`voltage_axis_x/y` 等属性别名，避免无关测试和调用方大面积改动。

考虑过只给现有 `QChartView` 安装事件过滤器，以及直接复用 `HistoryChartView`。事件过滤器会把坐标映射、状态和提示散落到 `MainWindow`；历史视图则绑定时间轴、框选和记录抽稀，均不适合当前场景。

### D2. 背景与提示全部来自主题 token

`LiveChartView` 从 `views.theme.tokens("dark")` 读取 `plate`、`text`、`text_dim`、`border` 和曲线色。chart 与 view 两层背景都设置为 `plate`；标题使用 `text`，横轴标签使用 `text_dim`，纵轴标签和曲线使用各自语义色，轴线与网格使用 `border`。悬浮提示使用图表内的子 `QLabel`，通过 token 生成深色样式，并设置不接收鼠标事件，避免遮挡交互。

只设置 chart 或只依赖 QSS 会在视图四周留下系统底色，因此明确设置两层画刷。提示不再占用垂直布局空间，改为跟随鼠标并限制在视图范围内。

### D3. Ctrl / Shift + 滚轮按修饰键分轴缩放

`wheelEvent` 仅在图表已启用、绘图区有效、存在序列且修饰键包含 Ctrl 或 Shift 时接管。同时按下两个修饰键时 Ctrl 优先：Ctrl 只缩放横轴，Shift 只缩放纵轴。使用 `angleDelta().y()` 计算缩放步数，每级比例设为 1.2；向上缩小目标轴跨度，向下增大目标轴跨度。

通过 `mapToScene()` 将视口位置转换为 chart 场景坐标，裁剪到 `plotArea()` 后用 `QChart.mapToValue()` 取得鼠标对应的数据坐标。横轴缩放只使用映射点的横轴值和当前横轴跨度计算新范围，纵轴保持不变；纵轴缩放只使用映射点的纵轴值和当前纵轴跨度计算新范围，横轴保持不变。

电压和电流实例各自持有目标轴的缩放范围，互不联动。未带修饰键、横向滚动或图表禁用时调用父类实现，保持原有行为。处理成功时接受事件，避免继续向页面传播。

考虑过让 Ctrl 和 Shift 都触发双轴缩放，也考虑过联动两张图。前者无法明确区分用户意图，后者会让不同量纲互相牵制，因此采用修饰键与轴一一对应、图表彼此独立的方案。

### D4. 横轴缩放暂停自动跟随，双击恢复双轴

`LiveChartView` 维护 `_auto_follow` 和默认横纵轴范围。只有 Ctrl 触发横轴缩放时才暂停自动跟随；Shift 触发纵轴缩放时不改变 `_auto_follow`。`MainWindow` 每次替换序列后调用视图的 `follow_latest(latest_index)`，该方法仅在自动跟随开启时更新横轴。数据列表裁剪和序列替换不受影响。

双击时恢复横轴默认范围、纵轴默认范围，并重新开启自动跟随和隐藏提示。横轴缩放限制在当前有界数据窗口内，纵轴缩放限制在初始量程内。最小横轴跨度不小于 2 个采样序号，最小纵轴跨度不小于默认量程的 2%，保证轴有效且可持续微调。

考虑过任意轴缩放都暂停自动跟随，也考虑过新点到达时自动退出缩放。前者会让纯纵轴查看意外失去实时横轴，后者会让横轴缩放无法持续，因此均不采用。

### D5. 使用屏幕距离查找邻近采样点

视图在 `mouseMoveEvent` 中把指针映射到 chart 场景，遍历当前可见的最多 100 个点，用 `QChart.mapToPosition()` 计算各点屏幕位置；距离指针不超过 10 像素时显示提示。提示内容为“采样点 <序号>”和“<数值> <单位>”，数值保留两位小数。

找不到邻近点、指针离开绘图区、图表禁用或序列刚替换时隐藏提示。移除原 `QLineSeries.hovered` + `series.atX()` 的查点方式和常驻布局标签，避免缩放后命中错误、提示位置固定和显示所有点。

考虑过继续使用 `hovered` 信号。该信号只覆盖 Qt 判定命中的点，不能稳定表达“鼠标靠近”，且把点位查找留在视图外部，因此采用视图内的屏幕距离判定。

## Risks / Trade-offs

- [横轴缩放被实时采样覆盖] → 仅 Ctrl/X 缩放关闭自动跟随，数据更新只调用带状态的 `follow_latest()`；测试覆盖横轴缩放后连续追加采样，以及纵轴缩放后横轴继续跟随。
- [高 DPI 或图表边距导致指针与点错位] → 统一使用 `mapToScene()`、`mapToPosition()` 和 `mapToValue()`，不手写绘图区尺寸换算。
- [持续缩放产生反转、零跨度或过大范围] → 对横纵轴分别执行最小/最大跨度限制，并保持最小值小于最大值。
- [序列替换后提示仍指向旧点] → 每次替换数据时隐藏提示，下一次鼠标移动重新计算。
- [滚轮事件被图表或页面重复处理] → 仅在满足修饰键和绘图区条件时接受事件，其余情况交给父类。
- [深色提示与全局主题不一致] → 颜色只从 `tokens("dark")` 获取，并增加 chart/view 两层背景和提示可读性测试。
- [视图重构影响既有滚动测试] → 保留 `MainWindow` 现有图表属性别名，并原样运行 `test_live_curve_window.py` 的窗口、门控和中断指示测试。

## Migration Plan

本次仅改变视图呈现和交互，不涉及数据、配置或协议迁移。实施时先引入 `LiveChartView` 并保持现有属性接口，再接入数据更新，最后删除旧提示逻辑；通过现有滚动窗口、波形门控、Presenter 采样与记录测试作为回归门槛。若需回滚，撤销该功能分支的视图改动即可，已有采样和记录数据不受影响。最终合入 master 时必须使用 `git merge --no-ff`。
