# Spec Delta

## Purpose

在用户不下载、不自动升级的前提下，让应用能自行发现"上游发布了更新的版本"并安静地告知一次；探测过程必须与离线控制硬件这一主职能完全隔离，任何网络结果都不得影响设备控制通路。

## ADDED Requirements

### Requirement: 发布清单为机器可读的对外契约

系统 SHALL 以仓库内的发布清单 `update/latest.json` 作为"最新版本"的唯一对外信息源，清单 MUST 包含 schema 版本、版本号、发布日期与发布页地址。清单 MUST 可同时由 Gitee 与 GitHub 两个代码托管站点的原始文件地址提供，且内容一致。

#### Scenario: 清单 schema 不受支持

- **WHEN** 取回的清单其 schema 版本不被当前应用识别
- **THEN** 该次获取判定为失败并按候选源顺序尝试下一个源

#### Scenario: 清单字段缺失

- **WHEN** 取回的清单缺少版本号字段
- **THEN** 该次获取判定为失败，且不弹出任何提示

### Requirement: 多源顺序回退获取

系统 SHALL 按配置顺序依次尝试候选源，第一个解析成功的结果即为有效结果；单个源失败 MUST NOT 阻止后续源被尝试。候选源地址与顺序 MUST 可由用户配置。

#### Scenario: 首选源不可达

- **WHEN** 首选源连接失败而备选源正常返回清单
- **THEN** 系统采用备选源的清单并按需提示

#### Scenario: 全部源均失败

- **WHEN** 所有候选源都无法取回可解析的清单
- **THEN** 系统不向用户显示任何错误，仅在日志记录本次检查未成功

### Requirement: 探测与主职能隔离

新版本探测 SHALL 以非阻塞方式在应用启动后延迟执行，单次网络请求 MUST 有明确超时上限。探测 MUST NOT 阻塞应用启动、MUST NOT 改变设备状态、MUST NOT 使任何异常传播到界面线程或控制服务。以无界面模式运行时 MUST NOT 发起探测。

#### Scenario: 网络完全不可达时启动

- **WHEN** 在无外网环境下启动应用
- **THEN** 界面正常可用，串口连接与设备控制不受影响

#### Scenario: 无界面模式

- **WHEN** 应用以无界面模式运行
- **THEN** 不发生任何用于检查更新的外部网络请求

### Requirement: 仅在存在更新版本时提示

系统 SHALL 仅当远端版本严格大于本地版本时提示。版本相等、远端低于本地、或本地为非发布（开发）构建时 MUST NOT 提示。用户已选择忽略的同一版本 MUST NOT 再次提示。

#### Scenario: 存在更新版本

- **WHEN** 本地版本低于清单中的版本且该版本未被忽略
- **THEN** 系统提示存在新版本

#### Scenario: 已是最新版本

- **WHEN** 本地版本不低于清单中的版本
- **THEN** 系统不显示任何提示

#### Scenario: 开发构建

- **WHEN** 本地运行实例被标识为开发构建
- **THEN** 即使清单中的版本更高也不显示提示

#### Scenario: 忽略后不再提示

- **WHEN** 用户对某版本选择忽略，随后再次触发检查且该版本仍是最新
- **THEN** 该版本的提示不再出现

### Requirement: 非阻塞的状态栏提示与用户动作

新版本提示 SHALL 以主窗口状态栏的一条非模态信息呈现，MUST NOT 使用模态对话框打断正在进行的设备操作。提示 MUST 提供两个动作：打开系统浏览器访问发布页，以及忽略该版本。系统 MUST NOT 由提示直接触发文件下载。

#### Scenario: 查看发布页

- **WHEN** 用户在提示上选择查看发布页
- **THEN** 系统浏览器打开清单中的发布页地址，应用自身不下载任何文件

#### Scenario: 正在控制设备时收到提示

- **WHEN** 提示出现时用户正在调节输出
- **THEN** 用户当前的焦点与操作不被打断，可继续使用界面

### Requirement: 检查节流与状态持久化

系统 SHALL 记录每次成功检查的时间，并在距上次成功检查不足配置间隔（默认 24 小时）时跳过检查。上次检查时间与已忽略版本 MUST 持久化到本机配置，且 MUST 沿用与其他运行时状态相同的存放规则以便在升级后仍然保留。

#### Scenario: 间隔内重复启动

- **WHEN** 距上次成功检查不足一个间隔时再次启动应用
- **THEN** 本次启动不发起检查请求，已有提示按持久化状态决定是否显示

#### Scenario: 重启后保留忽略记录

- **WHEN** 用户忽略某版本后退出并重新启动应用
- **THEN** 该版本的提示不再出现

### Requirement: 用户可完全关闭自动检查

系统 SHALL 提供关闭自动检查的开关（配置项与启动参数任一形式即可）。关闭后 MUST NOT 发起任何用于检查更新的外部网络请求，版本展示不受影响。

#### Scenario: 关闭后启动

- **WHEN** 用户关闭自动检查后启动应用并持续运行
- **THEN** 不发生外部检查请求，关于页仍正常显示当前版本

### Requirement: 不下载不自动升级

系统 MUST NOT 下载发布资产、MUST NOT 替换或写入应用自身文件、MUST NOT 静默启动安装程序。新版本提示的范围到"告知并给出发布页地址"为止。

#### Scenario: 存在新版本时的全部副作用

- **WHEN** 检查发现新版本且用户未做任何动作
- **THEN** 除界面显示一条提示与写出一条持久化状态外，不产生任何文件写入或程序启动
