# Design

## Context

动机见 `proposal.md` 的 Why，行为契约见 `specs/ui/live-curve/spec.md`。当前 `groupBox_8` 是默认未勾选的可勾选 `QGroupBox`，Qt 已将其中的两个 `QChartView` 禁用；但 `MainWindow.update_voltage()` 和 `update_current()` 仍无条件调用 `_update_chart_data()`，后者持续增加数据计数、裁剪窗口、替换序列并移动坐标轴。

设备采样由 `Presenter.refresh_voltage_current()` 每 500 毫秒执行，一次成对采集同时服务读数、实时曲线和记录。该链路现有测试保证每轮只读取一次电压和一次电流，因此本次变更 MUST NOT 把波形开关下沉到 Presenter 或设备层。

## Goals / Non-Goals

**Goals:**

- 在曲线更新的唯一入口实施门控，未勾选时不执行任何曲线数据或坐标轴更新。
- 保留 Qt 对图表子控件的原生禁用行为，同时保持复选框本身可操作。
- 让暂停期间的读数、悬浮窗、异常提示、周期采样和记录继续工作。
- 用真实 `MainWindow` 的 offscreen 测试覆盖视觉状态和数据行为。

**Non-Goals:**

- 不停止或降低设备采样频率，不改变记录文件内容与缺口判定。
- 不新增 Presenter 状态、Qt 跨层信号、后端接口、协议字段或持久化配置。
- 不修改 `.ui`、主题、图表样式、滚动窗口宽度或坐标轴含义。
- 不实现暂停区间的空白、断线或时间轴补偿，也不补绘暂停期间的数据。

## Decisions

### 在 `_update_chart_data()` 入口读取勾选状态

在检查 `_chart_initialized` 的同时检查 `self.ui.groupBox_8.isChecked()`；未勾选时立即返回，且返回位置 MUST 在数据计数、列表裁剪、序列替换和坐标轴设置之前。

这样电压和电流都经过同一个门控，不会出现只停一条曲线或重复条件判断。读数与悬浮窗更新发生在调用图表入口之前，因此自然不受影响。

备选方案：

- 在 `update_voltage()` / `update_current()` 中门控：需要重复条件，且容易误伤读数更新。
- 在 Presenter 中停止采样或任务：会同时停止读数和记录，违反本次确认的范围。
- 新增波形专用定时器：当前曲线与采样同源，拆成两个定时器会引入额外设备读取和一致性问题。

### 直接使用现有复选框作为唯一状态来源

不新增 `waveform_enabled` 副本，不连接 `toggled` 到 Presenter。Qt 在 `QGroupBox` 勾选状态变化时自动启用或禁用子控件；规划阶段已用项目 `.venv` 的 offscreen 探针确认：未勾选时新增到布局中的 `QChartView` 也为禁用，勾选后恢复，取消勾选后再次禁用。

因此无需手动调用图表视图的 `setEnabled()`，避免与 `QGroupBox` 的子控件状态机冲突。应用启动时沿用 `.ui` 的默认未勾选状态。

### 暂停不清空已有曲线，也不缓存跳过样本

未勾选时直接丢弃进入图表入口的新值，不增加 `voltage_data_count` / `current_data_count`，也不写入任何待恢复队列。重新勾选后，下一次有效采样正常进入原有滚动窗口。

该选择保持改动最小，并避免暂停很久后恢复时一次性补绘大量点。已有曲线在暂停期间保留但处于禁用状态；恢复后横轴仍表示“已显示的采样序号”，不表示暂停的墙钟时间。

### 调整现有滚动窗口测试的前置状态

现有 `TestRollingWindow` 使用默认未勾选的窗口并直接喂入 5000 个样本。实现门控后，这些用例 MUST 先显式勾选“显示波形”，否则它们验证的是暂停行为而非滚动窗口。新增开关测试则保留默认未勾选状态，分别断言：

- 初始复选框未勾选，两个图表视图禁用，复选框本身仍可操作。
- 未勾选时连续更新电压/电流，曲线点数、数据计数和坐标轴不变，读数和悬浮窗仍更新。
- 取消勾选已有曲线后，后续样本不改变曲线快照。
- 重新勾选后图表恢复可用，下一组样本只新增后续点，不补绘暂停样本。

## Risks / Trade-offs

- [在视图层门控无法直接证明记录继续] → 保持 Presenter 与记录代码不变，并运行 `test_recording_wiring.py` 与 `test_sampling_robustness.py`，验证每轮读取次数、成对写入和失败恢复均未回归。
- [Qt 子控件禁用行为属于框架语义，未来改 UI 结构可能失效] → 将两个 `QChartView.isEnabled()` 和复选框可用性纳入 offscreen 回归测试；若未来结构改变，测试会先暴露差异。
- [暂停后折线会连接暂停前后的可见点，无法表达时间空洞] → 本次规格明确不承诺时间空洞呈现；保持现有采样序号横轴语义，未来如需断线或空白应另立行为变更。
- [默认门控会使原有未勾选的滚动测试失败] → 在测试 setup 中显式启用波形，区分“滚动窗口测试”和“显示开关测试”，不放宽断言。

## Migration Plan

1. 后续实施按项目约束创建独立 git worktree 和修复分支，不在 master 上直接修改。
2. 在视图层增加门控并调整、新增 offscreen 测试，不涉及数据迁移或配置变更。
3. 运行波形视图、采样鲁棒性和记录接线测试；必要时运行相关 UI 测试集。
4. 审核后以 `git merge --no-ff` 将修复分支合入 master。
5. 如需回滚，恢复该修复提交中的视图与测试改动即可；无需迁移用户数据或记录文件。
