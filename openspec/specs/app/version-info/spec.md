# app/version-info Specification

## Purpose
让应用在任何运行形态下都能回答"我是哪个版本"：版本号只有一处定义，界面、日志、可执行文件元数据与控制通路回包一律由它派生，并且发布动作本身会校验它与 git tag 是否一致。

## Requirements

### Requirement: 应用版本单一真源

应用版本 SHALL 只在仓库内一处定义，界面展示、启动日志、可执行文件元数据与控制通路回包中的版本 MUST 全部由该定义派生。系统 MUST NOT 存在第二处需要人工同步维护的版本值。

#### Scenario: 变更版本后各落点同步

- **WHEN** 版本定义被修改为新的版本号并重新构建
- **THEN** 窗口标题、关于页、启动日志与可执行文件属性显示的版本号均为新值

#### Scenario: 不存在第二处版本常量

- **WHEN** 检索仓库内的版本定义
- **THEN** 除唯一真源外，其余位置只出现对该定义的引用而不出现字面版本号

### Requirement: 版本号格式与开发构建标识

版本定义 SHALL 采用 `主.次.修订` 三段数字的语义化格式，并 SHALL 附带仅构建期可得的来源信息（提交标识与构建时间）。构建期来源信息缺失时，系统 MUST 将该运行实例标识为非发布（开发）构建，MUST NOT 猜测或伪造来源信息。

#### Scenario: 源码直接运行

- **WHEN** 未经打包、直接以源码方式启动应用
- **THEN** 版本号取自版本定义，来源信息显示为开发构建标识

#### Scenario: 发布构建

- **WHEN** 由发布流程基于版本 tag 构建
- **THEN** 版本号与该 tag 一致，且来源信息包含实际提交标识与构建时间

### Requirement: 界面展示当前版本

主窗口 SHALL 展示当前应用版本：窗口标题 MUST 含版本号，「关于」页 MUST 展示版本号与构建来源信息。版本展示 MUST NOT 遮挡或替换既有的设备控制操作区域。

#### Scenario: 启动后查看标题与关于页

- **WHEN** 应用启动完成后查看窗口标题并切到「关于」页
- **THEN** 两处显示的版本号一致，且与启动日志中记录的版本一致

### Requirement: 可执行文件携带版本元数据

构建产物的可执行文件 SHALL 携带 Windows 文件版本与产品版本元数据，其值 MUST 等于版本定义中的版本号；产品名称 MUST 与实际应用名一致。

#### Scenario: 查看 exe 属性

- **WHEN** 在 Windows 中查看构建产物的文件属性详细信息
- **THEN** 文件版本与产品版本显示为当前版本号

#### Scenario: 未定义版本时构建失败

- **WHEN** 版本定义缺失或格式不符合约定而执行构建
- **THEN** 构建过程报错退出，不产出元数据缺失的可执行文件

### Requirement: 发布 tag 与版本真源一致

发布流程 SHALL 在版本 tag 与版本真源不一致时中止并明确报错，MUST NOT 产出不一致的发布物。同一约束 MUST 覆盖对外发布的最新版本清单：清单中的版本与 tag 不一致时发布同样 MUST 失败。

#### Scenario: tag 与真源不一致

- **WHEN** 发布流程收到形如 `v1.2.0` 的 tag 而版本真源为 `1.1.0`
- **THEN** 发布流程失败并指出两个值的差异

#### Scenario: 清单版本漂移

- **WHEN** 发布清单中的版本与本次 tag 不一致
- **THEN** 发布流程失败，不产生可供用户检查到的新版本记录
